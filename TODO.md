# Figural Character Studio — Delivery ToDo

- [x] **Adult-only safety and consent gate** — Require the creator to confirm that every character is a fictional adult (18+), no real identifiable person is being replicated, and they possess the rights and consent required for the intended use. Block minors, ambiguous youth, non-consensual scenarios, and sexualized replicas before generation and export; label output as fictional adult content.
- [x] **Guided native Android character studio** — Deliver a portrait-first Expo/React Native workflow for creating fictional adult characters from scratch, including an adult-only welcome screen, project name, age confirmation, and a clear no-payment/no-subscription/no-credit user experience.
- [x] **Photorealistic 3D-like generation pathway** — Implement real server-side image-generation requests for full-body and portrait renders, driven by the editable character specification, with generation validation, queue/progress states, recoverable failures, and no simulated render completion.
- [x] **Character customization controls** — Provide editable adult age, body proportions, facial structure, skin tone, hair, eyes, wardrobe, pose, expression, lighting, camera angle, and scene/background controls appropriate for mature creative workflows.
- [x] **Consent-bound reference-image input** — Let a creator select an image from the Android media library and carry its selected visual features into a newly generated character through the real image service. Require affirmative attestations that the source depicts a fictional adult or a consenting adult with rights to use the image; reject minors, ambiguous youth, non-consensual scenarios, and sexualized replicas of identifiable real people. Do not persist the raw source image after the generation request.
- [x] **Multi-view consistency workflow** — Support a complete character sheet containing front, side, rear, portrait, and posed view slots that retain the same saved character identity/settings and can be generated individually.
- [x] **Projects, presets, and history** — Persist character projects, reusable presets, generation settings, versions, render metadata, provenance metadata, and completed render records using the managed database.
- [x] **Gallery, exports, and rights confirmation** — Provide a gallery to review and organize completed renders; require a second consent/rights confirmation before exporting original-resolution images or transparent-background assets; export actual completed assets with configurable provenance metadata.
- [x] **Durable assets and native branding** — Transfer completed render bytes to managed storage, persist stable asset references, use a distinct square Figural launcher icon across required Android/Expo assets, and retain application identifiers.
- [x] **Free end-user product** — Exclude subscriptions, credits, in-app purchases, paywalls, and any requirement for an end user to provide a paid API key. Do not present an app user with a payment workflow.
- [x] **Validation and handoff** — Applied the database migration; passed TypeScript, Expo lint, test, server-build, Expo-config, live renderer, reference-image, signed-export/provenance, and verified-alpha validations; started and checked Metro/API listeners; inspected the mobile web preview; and prepared a checkpoint-ready Android project. An Android release artifact is only claimed after an actual Dashboard build result.
